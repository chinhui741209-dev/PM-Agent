# 01 軟體需求（ASPICE SWE.1 / ISO 26262-6 §6）

> 最後更新：2026-06-01 ｜ 對應 git：9bdeecc ｜ 由 skill：end-of-work

> 註：本專案（PM-Agent）為 WBS 產生與 Jira 部署工具，非安全關鍵系統；以下需求為功能需求，作為追溯範例。

| ID | 需求敘述 | 來源 | 對應架構 |
|---|---|---|---|
| SR-001 | 系統應接受純文字或檔案（docx/pdf/markdown/xlsx）作為需求輸入，並正規化為純文字。 | 產品需求 | ARC-002, ARC-003 |
| SR-002 | 系統應能從 Excel 輸入中抽取交付物清單（每列首個非空欄）。 | 產品需求 | ARC-003 |
| SR-003 | 系統應使用 LLM 將需求拆解為 WBS 階層（epic→story→task→subtask）。 | 產品需求 | ARC-004 |
| SR-004 | 系統應為每個 WBS 節點建議負責單位，且限定於使用者提供的可用單位清單。 | 產品需求 | ARC-004, ARC-008 |
| SR-005 | 系統產生的所有排程日期應落在「今天」與「交付日」之間。 | 產品需求 | ARC-004 |
| SR-006 | 系統應容錯處理 LLM 的非標準/雜格式輸出（裸陣列、包裝層、字串化清單、不合法型別），不得導致整批失敗。 | 強健性需求 | ARC-004 |
| SR-007 | 系統應逐節點驗證 WBS（型別、負責單位、日期區間、依賴一致性）並回報問題清單。 | 品質需求 | ARC-008 |
| SR-008 | 系統應能將確認後的 WBS 部署至 Jira Cloud，建立 Epic/Story/Task 階層、里程碑（Version）、負責單位（label）與初始狀態。 | 產品需求 | ARC-005 |
| SR-009 | 系統應記錄每次 WBS 產生的請求與模型原始輸出（JSONL），供回測與稽核。 | 可稽核性需求 | ARC-006 |

## 待補 / 缺口
- 無「軟體安全需求（含 ASIL）」—本專案非安全關鍵，故 ISO 26262-6 §6 之安全需求標為**範圍外**。
